## 1. Governance & Overview

All development in this repository strictly adheres to Bob Protocol SDLC standards. No work loop or sprint planning proceeds without this document.

### Architecture Topology
The tag tools moved to their own repo, **ntag-tools** (`git@github.com:drusifer/ntag-tools.git`, local `~/Projects/ntag-tools`; it has its own `docs/SDLC.md`): `shared` (UID, TagKeys, mask_key), `ntag_keys` (key model + CSV/memory/k3s stores), `tag_validator_service`, `sdm_provisioner`. They share one version and are built into wheels (`make dist` there). This repo consumes the `shared`, `ntag-keys` and `tag-validator-service` wheels (pinned in `game_server/pyproject.toml`).
1. **Game Server (`game_server/`)**: Flask gameplay server, coin message service, VIP contact endpoints, Twelve Clans sticker catalog, and real-time polling state manager.
2. **Sticker art (artai)**: Artwork is generated by the sibling `artai` tool, pip-installed editable from `../artai` (`ARTAI_SRC=`) into a dedicated `.venv-art/` by `make install-art`; targets `art-status`, `art-generate`, `art-pack`, `art-review`, `art-verify`. The workspace `.venv` is not touched.

## 2. Tooling, Runtime & Environment

- **Primary Runtime**: Python 3.11+
- **Virtual Environment**: workspace root `.venv`, created by `make venv` (installs the game's dependencies and the ntag-tools wheels from `NTAG_WHEELS`, default `~/Projects/ntag-tools/dist`; run `make dist` in ntag-tools first). `make install-all` then installs the game editable.
- **Container Runtime**: Docker / Podman / containerd / k3s.
- **Automation Interface**: `make` is mandatory for all builds, tests, lints, and container operations. No manual out-of-band commands that bypass `make`.

### Makefile Targets (this repo)
- `make venv`: create `.venv` with game dependencies and the ntag-tools wheels.
- `make test-game-server` / `make test-all`: run the game's tests (tag tools are tested in ntag-tools).
- `make vendor-ntag-wheels`: copy the pinned ntag-tools wheels to `build/wheels` for the image build.
- `make export-game-server-image`: build the game image from those wheels, boot-check it read-only with no network, and export `dist/game-server-$(VERSION).tar`.
- `make deploy-forgejo`: publish the game image to the pi-patch Forgejo. The validator image is built and published from ntag-tools.
- `make run-game-server`, `make clean`, and the sticker-art targets (`install-art`, `art-*`).

- **Branching**: Features and sprints execute on `main` or designated feature branches.

## 4. Kubernetes / k3s Secret Governance for Tag Keys

(Now implemented in ntag-tools' `ntag_keys` k3s store; the provisioner writes keys into the store directly and a validator in `TAG_VALIDATOR_MODE=validate` exposes no key routes. See `docs/DECISIONS.md` #15.)

- Tag keys (K0, K1 and K3) are stored as Kubernetes `Secret` resources in the target k3s cluster namespace (default: `tag-secrets` or `default`).
- Secret Naming: `tag-key-<asset_tag>` or `tag-key-<uid_lowercase>`.
- Secret Labels:
  - `app.kubernetes.io/name`: `tag-validator-service`
  - `app.kubernetes.io/component`: `k3-secret`
- Data Fields:
  - `uid`: 14-hex character Tag UID (e.g. `04B7664A2F7080`).
  - `k3`: 32-hex character SDM MAC Key (AES-128).
  - `counter_offset`: Optional offset tracking.
- Stateless Validator Constraint: The validator microservice maintains **zero persistent local state** outside the secret store.
